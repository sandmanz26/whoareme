# whoareyou

A directory of tech people and their real work. Two deployables in one repo:

- **`/` — the SPA.** React 19 + Vite + Tailwind v4. Integrates with the API via
  Axios + TanStack Query. Can still run against static fixtures and `localStorage`
  as a local fallback.
- **`/server` — the API.** Node + Express 5 + MongoDB (native driver), TypeScript.

The SPA still runs with no backend at all; the API is the production path.

## Read first

- [`docs/FRONTEND_RULES.md`](docs/FRONTEND_RULES.md) — **mandatory reading before
  any frontend change.** Stack decisions, component conventions, API patterns,
  styling rules. If you are an AI assistant, read this before touching the SPA.
- [`AGENTS.md`](AGENTS.md) — **orientation for an agent picking this up cold.**
  Two minutes, then it routes you to the right deep doc.
- [`CHANGELOG.md`](CHANGELOG.md) — what changed, when, and why it was decided
  that way. Includes every bug found and the invariant it became.
- [`docs/PROJECT_CONTEXT.md`](docs/PROJECT_CONTEXT.md) — **the complete
  handover.** Start here if you have no other context.
- [`docs/ENGINEERING.md`](docs/ENGINEERING.md) — front-end architecture and the
  invariants that break non-obviously.
- [`docs/BUSINESS.md`](docs/BUSINESS.md) — thesis, taxonomy, load-bearing rules.
- [`docs/TEMPLATES_AND_MOTION.md`](docs/TEMPLATES_AND_MOTION.md) — the work
  template system (archetypes × craft) and case-study motion.
- [`docs/DATABASE.md`](docs/DATABASE.md) — collections, indexes, every query.
- [`server/README.md`](server/README.md) — API surface and how to run it.

## Commands

```bash
npm run dev                # SPA on :9800
npm run build              # tsc -b && vite build
npm run export:fixtures    # regenerate server/fixtures/*.json from src/data

cd server
npm run dev                # API on :4000
npm run db:setup && npm run db:seed
npm run test:smoke         # 125 assertions against an ephemeral replica set
```

## Rules that are not negotiable without a stated reason

1. **Frontend approved stack is defined in `docs/FRONTEND_RULES.md`.** Do not
   introduce libraries outside that list without a stated reason.
2. **The SPA must keep working with no API.** Static fixtures and
   `localStorage` behind `useAccount` stay the fallback path for local dev.
3. **The API never imports from the SPA's source tree.** It reads
   `server/fixtures/*.json`, regenerated by `npm run export:fixtures`.
4. **No hard-coded colours.** Tokens live in `src/index.css` under `@theme`.
5. **Simulated data must be labelled.** The local traffic history is generated
   and the panel says so. Keep that disclosure.
6. **Proof points are "Results claimed", never verified facts.**
7. **Two published entries per topic, per person.** Enforced client-side for UX
   and server-side by a guarded atomic update. Neither is optional. The seeded
   fixtures respect it too — do not add seed data that breaks it.
8. **Topics have two kinds.** `industry` carries a business case; `practice`
   (design ops, hiring, reliability, accessibility, leadership, devex) does not.
   They share one axis and one quota, and the filter groups them so a practice
   is never read as a market.
9. **Check §11 of `docs/ENGINEERING.md` before touching cards, grids, the panel
   router, in-page anchors or the topic quota** — each item there is a bug that
   already happened.

## Verifying a change

**SPA:** no test suite. Drive a real browser and assert no console errors on
every route, no horizontal overflow at 360 / 390 / 768 / 1024 / 1440, and that
register → panel → publish → appears-on-home still completes.

**API:** `cd server && npm run test:smoke`.
